## 코딩 스타일
- 명확하고 간결한 코드 작성
- 불필요한 주석 추가하지 말것
- 주석은 반드시 영어로, 아주 간결하게, 인간 개발자가 작성한것처럼 핵심만 들어가있어야함.
- 내용이나 함수 이름으로 쉽게 역할을 이해할수 있는 곳에는 주석을 넣지않아야함.
- 함수 내용이 길어지는 경우에도, 어렵고 이해하기 힘든 스코프에만 주석을 넣어야함.

## 워크플로우
- 구현시에 사용자 의도가 명확하지 않은 경우 사용자에게 물어볼것.
- 사용자에게 코드를 설명할때는 파일 이름과 함께 전달할것.
- 현재 작업의 고려 대상 영역이 파일 3개가 넘어가면 codex에게 리뷰를 부탁할것. (gpt-5.4 사용)
- Codex 호출 시: Codex는 세션 간 context 유지 안됨 → **한 번에** 전체 영역을 전달해야 함(분할 금지). Codex가 코드 읽고 파악할수 있도록 코드 붙여넣지 말고 파일 경로 또는, CL, 커밋 번호만 전달. **호출 전 프롬프트 사용자에게 보여주고 허락받기**.

## 크래시 분석
- 크래시 발생 조건이 명확하다면, 해당 조건에서만 발생하는 이유를 찾을것.
- 찾은 원인이 정말 해당 조건에서만 발생하는 이유가 될수 있는지 한번더 체크할것.

## UE 개발 하네스
- **모든 언리얼 코드 작업 시 반드시 `ue-dev-harness` skill을 먼저 활성화할것** (코드 분석, 질문 답변 포함)
- 활성화 후 해당 skill의 Phase를 따를것
- **프로젝트별 빌드 커맨드, 테스트 절차, 운용 정보**는 `~/.claude/skills/ue-dev-harness/references/projects/`에 저장 (WorkHistory 아님)
