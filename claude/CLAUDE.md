## 코딩 스타일
- 명확하고 간결한 코드 작성
- 불필요한 주석 추가하지 말것
- 주석은 아주 간결하게, 인간 개발자가 작성한것처럼 핵심만 들어가있어야함.
- 내용이나 함수 이름으로 쉽게 역할을 이해할수 있는 곳에는 주석을 넣지않아야함.
- 함수 내용이 길어지는 경우에도, 어렵고 이해하기 힘든 스코프에만 주석을 넣어야함.

## 워크플로우
- 구현시에 사용자 의도가 명확하지 않은 경우 사용자에게 물어볼것.
- 코드 분석시 현재 세션에서 확인하지 않은 코드는 함수 이름만 보고 판단하지 말고, 반드시 변수레벨에서 어떻게 바뀌는지 확인할것.
- 자신에게 항상 확실한지 되물을것. 확실하지 않으면 다시 코드로 돌아가 확인할것.
- 정말 불가능한 경우를 제외하고 스스로 테스트 코드를 만들어 테스트할것.
- 각종 커맨드로 테스트 상황을 만들어야하는 경우 사용자와 논의할것.
- 사용자에게 코드를 설명할때는 파일 이름과 함께 전달할것.

## 크래시 분석
- 크래시 발생 조건이 명확하다면, 해당 조건에서만 발생하는 이유를 찾을것.
- 찾은 원인이 정말 해당 조건에서만 발생하는 이유가 될수 있는지 한번더 체크할것.

## WorkHistory (중앙 집중식 장기 기억) - **CRITICAL**

> **코드 분석, 시스템 탐색, 새로운 정보 발견 시 반드시 즉시 기록!**

- 위치: `~/WorkHistory/`
- 작업 시작 전 `~/WorkHistory/_index.md` 확인
- 프로젝트 구분: `~/WorkHistory/context/projects.md` 참조
- 작성 규칙: `~/WorkHistory/context/writing-guide.md` 참조

### 핵심 규칙
1. **기록 없이 대화 종료 금지** - 분석 결과는 발견 즉시 기록
2. **모든 문서에 핵심 요약 필수** - 파일 최상단 2-3줄
3. **topics/ 하위에 프로젝트별 저장** - pbb/, pubg/, pubg2/, ctu-example/
4. **task/topic 구분 없음** - 해당 시스템 폴더에 평탄하게 저장
